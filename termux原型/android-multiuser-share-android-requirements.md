# Android 多用户共享：原生 App 需求书

## 1. 项目定位

将现有基于 Termux 的“多用户共享”原型重做为独立 Android 应用。应用在一个 Android 用户中运行本地共享服务，手机上的其他 Android 用户通过浏览器访问该服务，在不同用户之间交换文本和文件。

本项目是一个 Vibe Coding 项目，面向小范围发布与日常个人使用。

## 2. 首版目标

- 不依赖 Termux、Python、命令行或手动部署。
- 用户安装 App 后可在界面中一键启动/停止共享服务。
- 服务运行时在通知栏显示状态，尽量避免被系统后台清理。
- 其他 Android 用户通过 `http://手机局域网IP:端口` 在浏览器访问。
- 支持文本和文件的双向上传、查看、下载、批量操作与删除。
- 默认提供访问密码保护，但允许用户明确选择关闭。

## 3. 使用场景

1. 用户 A 在主用户空间启动服务。
2. App 显示服务地址、运行状态和访问二维码。
3. 用户 B 切换到另一 Android 用户空间，用浏览器扫码或输入地址访问。
4. 任一用户上传文本或文件；内容保存在运行服务的用户 A 中。
5. 另一用户下载、复制或删除已共享内容。

## 4. 角色与边界

### 4.1 服务端用户

安装并运行 App 的 Android 用户。该用户拥有共享数据和服务控制权。

### 4.2 访问用户

同一手机的其他 Android 用户，或同一 Wi-Fi 下被允许访问的设备。首版通过浏览器使用共享页面，无需安装 App。

### 4.3 数据边界

- 所有共享文本、文件、密码和配置保存在服务端用户的 App 私有目录。
- 不使用云端账户或第三方服务器。
- 同一 Wi-Fi 的设备也可以访问，因此必须向用户明确提示风险。

## 5. 功能需求

### 5.1 原生控制页

- 显示服务状态：未启动、启动中、运行中、启动失败。
- 提供“启动共享”“停止共享”按钮。
- 运行中显示局域网地址、端口、可复制地址和二维码。
- 显示当前访问保护状态：密码保护/公开访问。
- 首次启动前引导设置用户名和密码；用户名默认 `share`，密码至少 12 位。
- 可切换到公开访问模式；切换前需明确展示风险提示。
- 可修改用户名和密码。
- 提供共享数据目录占用情况与“打开数据管理”入口。

### 5.2 常驻服务

- 使用 Android 前台服务运行本地 HTTP 服务。
- 前台通知显示“多用户共享正在运行”、端口和停止操作。
- 服务应在 App 切换到后台后继续运行；若系统结束服务，通知和控制页应能反映已停止状态。
- 默认监听局域网可访问的地址，默认端口为 `8080`；允许在设置中修改端口。
- 端口被占用时给出明确错误与可操作建议。

### 5.3 浏览器共享页面

页面适配手机浏览器，包含“文本”和“文件”两个 Tab。

#### 文本 Tab

- 输入并保存多条共享文本。
- 每条文本以列表展示：第一行标题、最多三行摘要、字数、保存时间。
- 支持展开/收起全文、一键复制、勾选多条后删除。
- 删除必须通过“勾选 → 删除所选”流程，并二次确认。
- 默认按保存时间倒序排列。

#### 文件 Tab

- 支持一次选择和上传多个文件。
- 单文件默认最大 512 MB；超限时显示清晰错误。
- 上传时可设置 N 分钟后过期；留空则永久保存。
- 过期文件在后续访问时自动清理。
- 默认按上传时间倒序排列。
- 支持勾选多个文件后：逐个触发浏览器下载、下载 ZIP、删除所选文件。
- 删除必须通过“勾选 → 删除所选”流程，并二次确认。
- 图片文件显示缩略图；非图片显示通用文件图标。

#### 文件视图

- 网格模式：上半部为图片缩略图或文件图标，下半部为选择框和最多两行文件名。
- 列表模式：紧凑单行，列为“选择框｜缩略图（可开关）｜文件名｜大小”。
- 列表模式关闭缩略图时隐藏缩略图列；打开时显示约 32 px 缩略图。
- 用户选择的视图模式与缩略图开关保存在浏览器本地，下次访问保持。

### 5.4 认证与安全

- 可选 HTTP Basic Authentication 或等价的轻量访问认证。
- 首次安装默认建议启用密码保护。
- 公开模式下，控制页和网页均显示“同一 Wi-Fi 的设备也可以访问”的警告。
- 不要求 HTTPS；文档和控制页需明确说明不适合传输高度敏感内容。
- 密码不得以明文暴露在页面、日志或分享地址中；本地保存应使用 Android 安全存储能力。

### 5.5 数据管理

- 共享内容默认存储在 App 私有目录。
- 支持在设置中选择/更改数据目录；更改前说明权限与迁移影响。
- 不因 App 更新、服务重启或配置更新删除已保存的文本和文件。
- 文件重名时自动生成不冲突的名称。

## 6. 非功能需求

- 最低支持 Android 版本待项目初始化时确定；优先覆盖仍常见的 Android 设备。
- UI 使用简体中文，优先适配手机竖屏。
- 服务首次启动到可访问应有明确状态反馈。
- 大文件上传应避免一次性占用过多内存。
- 浏览器页面不依赖外部 CDN，以便在无外网但有本地网络时仍可使用。
- 关键操作（启动失败、上传失败、认证失败、端口占用）必须给出人类可理解的提示。

## 7. 不在首版范围内

- 云同步、远程互联网访问、账号体系。
- 端到端加密或 HTTPS 证书管理。
- Android 用户之间直接读取彼此 App 私有目录。
- 原生访问客户端；首版访问端使用浏览器。
- 自动后台重启、开机自启和跨设备同步。

## 8. 建议技术方向

- Kotlin + Jetpack Compose：原生控制页与设置页。
- Android Foreground Service：常驻服务与通知控制。
- 内嵌轻量 HTTP 服务器：提供浏览器共享页面和上传下载接口。
- App 私有存储 + Android 安全存储：共享数据与认证配置。
- 网页前端可作为 App 内嵌静态资源提供，不依赖网络加载。

## 9. 验收标准

1. 新设备只需安装 APK、打开 App、完成首次设置并点击启动，即可得到可访问地址。
2. 在另一个 Android 用户的浏览器中，可用该地址成功访问并通过认证。
3. 两个用户均可上传文本和多文件，并在另一侧看到最新内容。
4. 图片可显示缩略图；网格与列表布局符合第 5.3 节。
5. 多文件下载、ZIP 下载、批量删除、文本复制、文本批量删除均可用。
6. 过期文件在到期后不再显示且被清理。
7. 停止服务后，浏览器不能继续访问；重新启动后历史数据仍存在。
8. 更新 App 后，既有文本、文件和认证设置仍保留。
